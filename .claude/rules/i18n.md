# Two languages, Vietnamese first

The operators read Vietnamese. English is the second language, carried for the colleagues
and auditors who do not. `DEFAULT_LOCALE` in `@undercroft/core` is `"vi"`, and it is a
product decision rather than a fallback — the reasoning is in `docs/adr/0012`.

Catalogues: `apps/ui/src/i18n/{vi,en}.ts` for the browser, a much smaller
`apps/control-plane/src/i18n/{vi,en}.ts` for the five emails and the refusals the server
writes, `apps/cli/src/i18n/{vi,en}.ts` for the CLI's help, prompts and envelope messages,
`apps/installer-cli/src/i18n/{vi,en}.ts` for the setup wizard's questions and sentences,
`apps/desktop/src/i18n/{vi,en}.ts` for the desktop app's wizard, tray and dialogs (one catalogue
for both of its processes, pinned by `i18n.test.ts`), and
`apps/mcp-widgets/src/i18n.ts` for the two MCP widgets, which answer in the language the host
names (`hostContext.locale`) and fall back to Vietnamese like every other door.
`vi.ts` is the source of truth for which keys exist in each. A CLI flag, command name or error
code is not translated: it is what a person types and an agent matches.

What a router procedure does is worded once, beside the router, in
`apps/control-plane/src/i18n/procedures.{vi,en}.ts`: one sentence per dotted path, read by
every caller that is not the browser (the CLI's help and `describe`, a model-context client's
tool list). Those two are keyed by the router rather than by `vi.ts` — both are typed
`Record<ProcedurePath, string>`, so a procedure with no sentence, or a sentence for one that
is gone, is a `tsc` error in either language. The CLI's `topics` are typed against the
router's namespaces the same way.

## NEVER

- **NEVER write a user-facing string in a component, a route, a handler or a service.** It
  will ship untranslated, and nobody will notice until a Vietnamese reader hits the one
  screen that is half in English — usually an error state, which is the worst moment for it.
  Add a key to `vi.ts` first; the compiler then requires `en.ts` to answer it.
- **NEVER build a sentence by concatenating translated fragments.** Vietnamese and English do
  not share word order, so a sentence assembled from pieces can only be right in the language
  it was assembled in. One key per sentence, with `{{name}}` interpolation.
- **NEVER choose a plural form with a ternary.** `count === 1 ? "customer" : "customers"` is
  an English rule; applied to Vietnamese it produces "1 khách hàngs". Use i18next's `_one` /
  `_other` and pass `{ count }`.
- **NEVER call `i18n.changeLanguage` from a component.** The Zustand store owns the locale and
  `@/i18n` projects it into i18next and onto `<html lang>`. Writing to i18next directly puts
  the user's choice where the store cannot see it, nothing persists it, and the tRPC link
  sends the server a different language from the one on screen. See `.claude/rules/state.md`.
- **NEVER localise a monetary amount.** `formatMoney` groups with `,` in every language,
  deliberately; only `formatCount` and `formatBytes` follow the reader.
  `.claude/rules/money.md`.
- **NEVER let a locale change a timezone.** The language changes the words and the digits,
  never the clock. In a browser, `@/lib/when` shows an instant in the **viewer's own zone** --
  the runtime's -- and a day typed into a form is that viewer's local day; a reader using
  Vietnamese in Singapore sees Singapore's clock. A cron expression is the exception: it is
  written in `SCHEDULE_ZONE` (Asia/Singapore) and its field says so (`cronHint`, `cronZone`).
  Text the server writes -- an email, a Lark card, a refusal -- cannot know its reader's zone,
  so it stays in Singapore time and names the zone (`formatWhen`). A time with no zone on it,
  an hour off from the reader's clock, is a wrong value that looks right. ADR 0149.

## Follow

- **A pure library takes `t` as its first argument** — `presentConnection(t, connection)`,
  `expiryNote(t, iso)`. It never reaches for a global translator, which is what lets a test
  render both languages in one run. Where a decision needs no words, it gets its own
  wordless function: `connectionFacts` beside `presentConnection`.
- **The locale travels as `Accept-Language`.** The tRPC link and the Better Auth client send
  it; `createContext` in `handlers/context.ts` negotiates it once per request onto
  `Context.locale`. A handler
  wording a refusal reads `ctx.locale`, never an ambient value — two concurrent requests in
  two languages must not answer each other's.
- **A vendor's name is not translated.** `HubSpot`, `Xero`, `Gmail`, `Google Drive`, and the
  role values `viewer` / `member` / `builder` / `admin`, stay as they are in both catalogues, and
  so does a permission key (`models:write`): it is what a refusal names and an agent matches.
- **The UI and control-plane catalogues are pinned by a test**, not only by types:
  `i18n.test.tsx` and `i18n.test.ts` compare key sets with plural suffixes stripped and assert that no key
  resolves to itself. A raw key rendered on a page passes every "is it non-empty" check.
