# ADR 0028: A workbook is read in process, and extract is scheduled by backlog

Two decisions from one investigation into why a spreadsheet synced from Google Drive was never searchable. A `.xlsx` is **read in this process**, with no new dependency and no new binary -- `services/extract/zip.ts` reads the container and `services/extract/xlsx.ts` the OOXML, while a pre-2007 binary `.xls` is refused by name as `legacy-xls-unsupported`. And an extract run is **due when there is work outstanding, not on a cadence**: `GET /v1/runs/extract-due` returns the `(tenant, source)` pairs holding a document nobody has read, and `flows/extract_due.yml` ticks it hourly. `poppler-utils` also joins the worker image, which is a correction rather than a decision -- `extractText.ts` had invoked `pdftotext` by name since [[ADR 0024: A document's text is readable by dbt]] and the binary was never installed, so every PDF on the server recorded `extractor-missing:pdftotext`.

**What was actually broken** is the interesting part: three faults stacked, each of which alone made the feature invisible rather than loud. The Drive sync was working, with a correct 262,887-byte spreadsheet row in `raw.documents`; `raw.document_text` held zero rows and 72 hours of logs held no extract event, because nothing anywhere called the extract verb; had anything called it, the dispatch handled `text/plain`, `application/pdf` and `application/msword` and nothing else; and `which pdftotext` in the running container answered "not found". Every layer reported success. That is the failure mode `CLAUDE.md` rule 2 is about, arriving through the **harness** rather than through a value -- a green sync, a green run, a green gate, and a Lake division truthfully printing "1 document, 0 readable" that nobody had a reason to read as a defect.

**Why the workbook reader is ours.** An `.xlsx` is a zip of XML, and the alternatives were measured against that: LibreOffice had already been rejected in a comment as "a container's worth of dependency for two files" when `application/msword` was declined, and accepting it for spreadsheets would have made that comment false rather than answered it; `xlsx2csv` and `in2csv` are Python, and while `CLAUDE.md` permits an invoked Python binary, each adds a venv, a pin and a second thing to upgrade for a format whose container is 120 lines of `node:zlib`; and an npm library's real cost is not bytes but that the worker is the one process holding `UNDERCROFT_SECRET_KEY`, where a transitive dependency is a supply-chain surface for a file format we can parse exactly. So the reader is deliberately **not** a zip library -- no writing, traversal, streaming, encryption or zip64 -- and anything it cannot read exactly returns `null` and becomes a recorded reason, never a partial read, because a half-parsed workbook is indistinguishable downstream from a short one.

**Cell values stay strings, exactly as the file wrote them.** A spreadsheet is the likeliest document in the platform to be full of amounts and `Number("1234.10")` is `1234.0999999…`; `.claude/rules/money.md` exists for precisely this, so nothing in the reader parses a value. A date is left as its serial for the same reason in a different direction: rendering it needs the workbook's format table, the 1900/1904 epoch flag and a timezone this layer has no business choosing, and a guessed date cannot be told from a real one. Sheet **names** are excluded too, because binding them to their parts means walking `xl/workbook.xml` and its rels, and without that "sheet1.xml is the first tab" is a convention that usually holds -- and usually is a guess.

**Why backlog and not cadence.** An ingest is due by the clock, a cadence the customer chose whether or not anything changed at the source; giving extract a cadence of its own would start a run over a settled tenant on every tick, forever, for a verb ADR 0024 measured at tens of minutes of CPU. `pendingScopes` reuses the exact predicate `pendingDocuments` already uses to decide which documents a run reads -- never read, or read from bytes whose `source_sha256` has changed, excluding tombstones -- and sharing it is load-bearing, because two definitions of "pending" drifting apart would appear as a flow that ticks forever over a tenant whose documents the run then declines to read. A settled pair falls off the list, which is what makes an hourly schedule cheap. It stays a **separate flow** from `ingest_due` rather than a chained task, for ADR 0024's reason unchanged: chained, an ingest's duration becomes a function of how much reading is outstanding, and a failed read looks like a failed sync -- two facts wearing one status.

Rejected: chaining extract to the end of each ingest; giving the control plane a "read documents" button, since a button makes searchability a thing someone remembers to do and the Lake division's "N documents, M readable" is the report rather than the trigger; shipping `tesseract-ocr` in the same change, because a 200 MB binary nothing calls is weight in the image and surface in the process, so it arrives with the reader that needs it while a scan keeps refusing as `needs-ocr`; and letting an unreadable workbook store its readable part, because a cut workbook that does not say it is cut reads as a complete one that simply lacks the row you were looking for -- the truncation case that **is** supported sets `truncated`, which is the difference.
