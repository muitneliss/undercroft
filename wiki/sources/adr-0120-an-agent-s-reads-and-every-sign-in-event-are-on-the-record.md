# ADR 0120 An Agent's Reads, and Every Sign-In Event, Are on the Record

Extends the audit log of [[ADR 0113 Every Action Is in the Audit Log and People Can Read It]] to what an agent reads and to the sign-in events it left out. It supersedes, for the CLI, `/mcp` and the assistant only, 0113's "plain reads are not actions", its `"none"` entry and its rejected option "log every call, reads included"; and it extends 0113's list of events written outside the router. Everything else in 0113 stands, and a read through the browser is still not recorded, for 0113's reason: the SPA polls.

Context. A person who lets an agent in ([[ADR 0044: An agent reaches Undercroft as a caller]], [[ADR 0060: An agent reaches Undercroft over MCP, with a credential a person holds]], [[ADR 0029: The assistant is an interleaf, and it acts only through the router]]) hands it their authority over every customer they belong to, and what it read with it -- a `lake.query` over raw records, the models, the run history -- left no trace. Four sign-in events were also missing: a bearer refused at `/mcp` or an export download (only the operator's `mcp_refused` line saw it, [[ADR 0062: A refused bearer is logged with its reason, and an access token lives eight hours]]), a consent given to a model-context app ([[ADR 0061: An MCP client signs its person in, and draws two widgets]]), a sign-out through Better Auth's own `/sign-out`, and a wrong one-time code for a real person's address.

Decision. (1) A read -- a query, or a POST `AUDITED` now marks `"read"` (was `"none"`: `lake.query`, `models.check`, `macros.check`, `bi.answer`, `bi.runQuestion`) -- is recorded when `ctx.channel` is `cli`, `mcp` or `assistant`, however it ends, and never for `web` (`isRecorded` in `handlers/audited.ts`). The decision is on the channel, not the credential, because the CLI holds a session and the assistant reuses the browser's. (2) A read's row copies nothing of its input but the tenant it named (SQL and questions may quote customer data), and the tenant is attributed by the same authority check as a refused attempt, since `audit.all` takes a tenant as a filter. (3) Four events: `auth.tokenRefused`, written once by `bearerContext` for every door that admits a bearer, every reason but `missing` (every OAuth client's first contact), naming the owner where an account was read, carrying the `upat_…` or `oauth:<client>` id and never the token, channel `mcp`; `auth.consentGranted`, an after-hook on `/oauth2/consent` (the provider writes the consent through its own adapter and offers no callback in 1.7.5) recording only an accepted answer that issued a code, the app as `oauth:<client>` and the scopes as stored, never the app's self-chosen name; `auth.signOut`, Better Auth's `session.delete.after` hook for a deletion made by `/sign-out`, which both ways out reach, so `session.signOut` becomes `"service"` and one sign-out is one row; and `auth.refused` becomes `refused` with a reason this log owns -- `NOT_INVITED`, or `WRONG_CODE`, `CODE_EXPIRED`, `TOO_MANY_ATTEMPTS` mapped from the email-OTP plugin's codes, for an admissible address only, and naming the `app_user` the address belongs to. (4) A row may name nobody: `actor` is nullable (`520_audit_log_unattributed_actor.sql`) for a token nobody here issued; the table stays append-only. (5) Better Auth's audit hooks are one plugin, `auditPlugin` in `handlers/authAudit.ts`, its session hooks contributed through `init`. (6) `AuditAction` covers every procedure path plus the events, and both UI catalogues label each, Vietnamese first.

Consequences: every agent call is now a row, and retention, unbounded since 0113, is nearer to needing its own decision; an unauthenticated caller can write a row (a garbage bearer at `/mcp`, as an uninvited code request already could), not rate-limited; an export downloaded through an agent's door is three rows (create, the route's own `bi.exports.get`, download); a read of the log through an agent door records itself; a write tool a read token names directly, refused by `/mcp` before the router runs, is recorded by the door through the same `recordCall` the middleware uses (path, `refused`, `WRITES_DISABLED`, the token, the tenant under the same authority check), while an unlisted tool, `tools/list` and `resources/read` are protocol traffic and leave no row; older `auth.refused` and `session.signOut` rows keep their shape.

Rejected: logging browser reads (polling drowns the actions); keeping reads out everywhere (an agent's reading stays invisible); copying a read's input into `detail`; a refused-bearer write in each door; recording `missing`; a placeholder actor for an unowned token; a router row for `session.signOut` beside a `/sign-out` hook; a new event for a wrong code; reading a consent from what the page sent rather than the stored row.
