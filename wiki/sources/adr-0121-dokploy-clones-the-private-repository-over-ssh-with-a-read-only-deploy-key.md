# ADR 0121 Dokploy Clones the Private Repository over SSH, with a Read-Only Deploy Key

Amends [[ADR 0049: Dokploy clones the compose file from main]] in the URL its decision names, and nothing else. The repository was made private, and the panel's credential-less HTTPS clone of `main` then failed every deploy (`fatal: could not read Username for 'https://github.com'`): v1.74.0 and v1.75.0 were built and published and never reached the host, while `preflight` passed both times because it reads the branch's file through the GitHub API with the workflow's own token rather than the way the host clones it.

Decision. The panel clones `git@github.com:muitneliss/undercroft.git` over SSH with an ed25519 key it holds (`undercroft-github-deploy-key`), generated by Dokploy's `sshKey.generate`, stored through `sshKey.create`, with no other copy; its public half is a read-only deploy key on this repository alone. `preflight` asserts the SSH URL (`COMPOSE_SOURCE` in `scripts/dokploy.ts`); everything else it asserts is 0049's. The organization had deploy keys disabled for every repository and now allows them.

Consequences: removing the key on either side fails the clone exactly as the private repository did, and rotating it is a new key in both places plus a `compose.update` naming the new `customGitSSHKeyId`; the key reads one repository and writes nothing; any admin of an organization repository can now add a deploy key. Rejected: making the repository public again (not this repo's decision), Dokploy's GitHub App (browser installation, and a `sourceType` change 0049's `preflight` refuses, for the same read access), and a token in the HTTPS URL (a credential in a displayed, compared field, expiring on its own schedule).
