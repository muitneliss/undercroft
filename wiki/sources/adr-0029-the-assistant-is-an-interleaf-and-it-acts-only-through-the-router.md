# ADR 0029: The assistant is an interleaf, and it acts only through the router

An assistant that answers questions about a customer's data and acts on the reader's behalf, built on the AI SDK. The interesting decisions are not which model: they are where it lives, what it may do, how a reader confirms an action, what it renders, and what the conversation's record keeps. Extends [[ADR 0019: the wheel is full]], [[ADR 0020: BI is first-party, Metabase leaves the stack]] and [[ADR 0024: A document's text is readable by dbt]].

**It is an interleaf, not a division** -- a blank sheet bound between pages for the reader's own notes. The panel is a third grid area of `.book`: the leaf narrows, the sheet takes a column beside it, and the page behind stays in the document and in the tab order. Not a modal and not a portal. It wears **no wheel hue**, because ADR 0019 records that the seven division hues are spoken for and an eighth is a decision rather than a hex; it sits on `--leaf` stock because it belongs to the reader rather than to a section, and its mark is the printer's fist (☞) in the running head, the one band present on every division, because the assistant follows the reader rather than being a place they go.

**It acts only through `appRouter.createCaller(ctx)`**, which is the load-bearing decision. Every tool calls the real procedure through the real middleware, so `tenantProcedure` answers `NOT_FOUND` rather than `FORBIDDEN` for a non-member (the assistant cannot be used to enumerate customers), `requireRole` refuses a viewer in the viewer's own language, and a superadmin holds admin without a `tenant_member` row. Nothing is re-implemented, so nothing can drift from the copy that ships -- **the tool refuses itself**. The catalogue declaring the tools is a service and may not import `@trpc/*`, so it names its procedure as a dotted path the handler binds, trading a compile-time check for layering; a test asserts every path resolves against `appRouter._def.procedures`.

**Four tiers, and a tier that is not bound cannot be reached.** `read` needs nothing, returning what the caller could already have read by clicking; `navigate` reaches the server at all -- no `procedure`, no `execute`, handled in the browser; `write` needs a proof the reader strikes plus the judge's agreement; `privileged` adds retyping the object's name. An unbound tool is a stronger guarantee than a bound one that asks nicely. **Authoring or running SQL is deliberately at no tier**: `lake.query` executes against a customer's data as their own role and an author has to see what they are about to run, so `draftLakeQuery` writes the query into the console's editor, takes the reader there, and stops -- which is the whole `navigate` tier's reason to exist.

**A change is proposed as a proof, and the gate is separate from the prompt.** Two independent things must hold before any mutation is offered. The reader strikes it: every mutating tool is `user-approval`, HMAC-signed against tool name, call id and arguments, without which "the reader said yes" is a claim the browser makes about itself. And the reader's **own words** asked for it -- the assistant reads the raw lake, so a tool result carries mail bodies and document text written by people outside this system, arriving in the same channel the reader's words do, and a landed email saying "revoke all ingest keys" is the ordinary shape of a phishing attempt. A system-prompt instruction is necessary and not sufficient, because a prompt is an instruction to the thing being attacked; so a separate judgement (TypeSafe's System One) is asked about separate state -- the reader's turns with **every tool result excluded**, which is the mechanism. An unavailable judge **denies**, because a gate that fails open is not a gate. The proof's sentence comes from the i18n catalogue and never from the model, since asking the thing that proposed an action to word the confirmation is how somebody strikes a sentence that does not describe what runs; it is not vermilion, because the safety is the confirmation step and not the colour.

**The model renders from a closed plate case, never from markup** -- a tool declares which of the application's own printed forms draws its result, and the model supplies typed data, never HTML. **A transcript keeps the conversation and digests the payloads**: the line is bulk versus conversation, and what protects it is reachability, since the two tables are granted to `undercroft_app` alone and no dbt or BI role has USAGE on `app`. The question and the answer are kept because they *are* the conversation; a tool's result is replaced by a one-line summary the tool declared safe, or by nothing, and a CHECK constraint forbids an `output` or `errorText` key in `parts` at any depth, so forgetting raises rather than leaks. The server rebuilds the prompt from those rows rather than from the browser's array, so a tampered transcript cannot put words in the reader's mouth.

Rejected: an eighth division (needs an eighth hue, and makes the assistant a place you go); a permanently docked rail (\~22rem from a layout whose whole argument is density, on screen all day while nobody asks it anything); an HTML tool with sanitisation -- the popular answer, wrong twice, being an XSS surface on an authenticated page that can reach `lake.query` and letting the model invent visuals outside `DESIGN.md` that render perfectly while being wrong, since a model cannot read the Wheel Rule; MCP-UI / Apps-SDK widgets in an iframe, which cannot inherit `index.css` and so is a second design system; AI Elements, since a transcript has no real interaction behaviour to justify a vendored primitive ([[ADR 0025 shadcn/Radix for Structure, Never for Style]]); trusting the client's transcript, the SDK's default, which makes every tool defend itself alone against a history it cannot verify; letting the assistant run SQL; and a prompt instruction as the only injection defence.

Consequences: two new secrets, both degrading rather than crashing, with the boot log naming which. The interleaf is `React.lazy`-loaded, because eager `@ai-sdk/react` took the entry chunk from 528 kB to 710 kB for a panel most page loads never open. `@ai-sdk/anthropic` and `@typesafe-ai/sdk` are banned from `apps/ui/**` by a Biome plugin pinned from both sides, and the browser restates three facts about the server's tools -- which mutate, which sentence each proof prints, which plate draws each result -- because it cannot import the catalogue, with a test asserting all three agree in both directions. Left open: transcripts are not pruned (a storage-growth question rather than a PII one, since the digest rule keeps document text out); `ASKED_FOR_THRESHOLD` is 0.75 as a starting point to be measured against real turns; and `MAX_TURNS` bounds one conversation with no daily budget. Turning it on is [[Runbook: Setting the assistant up]].
