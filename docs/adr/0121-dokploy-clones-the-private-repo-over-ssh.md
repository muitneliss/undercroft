# 121. Dokploy clones the private repository over SSH, with a read-only deploy key

- Status: Accepted
- Date: 2026-10-11
- Amends: [ADR 0049](0049-dokploy-clones-the-compose-file-from-main.md) (the URL its decision
  names; everything else in it is unchanged)

## Context

ADR 0049 has the panel clone the compose file from `main` at
`https://github.com/muitneliss/undercroft.git`, with no credential, which worked because the
repository was public. The repository was made private, and from then on every deploy failed
before it started: `fatal: could not read Username for 'https://github.com'`, then
`Fail to clone the repository`. v1.74.0 and v1.75.0 were built and published and never reached
the host; `preflight` passed both times, because it reads the branch's file through the GitHub
API with the workflow's own token, not the way the host clones it.

## Decision

The panel clones `git@github.com:muitneliss/undercroft.git` over SSH, with an ed25519 key it
holds (`undercroft-github-deploy-key`, Dokploy → SSH keys) whose public half is a **read-only**
deploy key on this repository alone. The private key was generated by the panel's own
`sshKey.generate`, stored through `sshKey.create`, and has no other copy. `preflight` asserts
the SSH URL in place of the HTTPS one (`COMPOSE_SOURCE` in `scripts/dokploy.ts`); the rest of
what it asserts is ADR 0049's.

The organization had deploy keys disabled for every repository; it now allows them, so that this
one could be added.

## Consequences

- A deploy needs the key: removing the deploy key on GitHub, or the key in the panel, fails the
  clone exactly as the private repository did. Rotating it is a new key in both places and a
  `compose.update` naming the new `customGitSSHKeyId`.
- The key reads this one repository and writes nothing. It is not a person's key and not a
  token with an organization's reach.
- Any admin of a repository in the organization can now add a deploy key to it.

## Options rejected

- **Make the repository public again.** That reverses a decision this repo does not own.
- **Dokploy's GitHub App as the source.** It needs the app installed through the browser and
  changes `sourceType` from `git` to `github`, which ADR 0049's `preflight` checks for, for the
  same read access a deploy key gives.
- **A token in the HTTPS URL.** It puts a credential into a field that is shown in the panel and
  compared by `preflight`, and a fine-grained token expires on a schedule the deploy does not
  know about.
